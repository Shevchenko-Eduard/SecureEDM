# Криптография

## Алгоритмы

### 1. Хэширование
**Что это:** односторонняя функция, которая превращает данные произвольной длины в короткий «отпечаток» фиксированной длины. Используется для проверки целостности, в подписях, в KDF. Восстановить исходные данные из хэша нельзя.

- **MD5** — устаревший, криптостойкость сломана (коллизии). Только для совместимости/контрольных сумм, не для безопасности.
- **SHA-1** — тоже устарел, коллизии практически найдены.
- **SHA-2** — семейство современных стойких хэшей.
  - **SHA-256** — стандарт де-факто, широко используется (TLS, подписи, блокчейн).
  - **SHA-512** — та же конструкция, но длиннее дайджест; быстрее на 64-битных платформах.
- **SHA-3** — новое поколение (конструкция «губка»), независимая от SHA-2 альтернатива на случай компрометации SHA-2.
- **BLAKE3** — очень быстрый современный хэш (дерево Меркла), хорошо параллелится; популярен в высокопроизводительных задачах.

### 2. Генерация асимметричных ключей
**Что это:** создание пары «открытый + закрытый ключ». Стойкость основана на математической трудности определённой задачи — по ней и группируются алгоритмы.

- **На основе факторизации чисел** — трудно разложить большое число на простые множители.
  - **RSA** — самый известный; ключи на основе произведения двух больших простых чисел.
  - **Rabin** — родственник RSA; стойкость эквивалентна факторизации (взлом = факторизация).
- **На основе дискретного логарифмирования** — трудно найти показатель степени в конечном поле.
  - **DSA** — стандарт цифровой подписи (только подпись, не шифрование).
  - **ElGamal** — базовая схема и для шифрования, и для подписи.
- **На основе эллиптических кривых (ECC)** — та же стойкость при гораздо меньших ключах (короче, быстрее, экономнее).
  - **ECDH** — протокол согласования общего секретного ключа.
  - **ECDSA** — подпись на эллиптических кривых.
  - **EdDSA** — современная детерминированная подпись (безопаснее ECDSA к ошибкам реализации).
    - **Ed25519** — быстрый и популярный вариант (128-битный уровень стойкости).
    - **Ed448** — более высокий уровень стойкости.
  - **X25519** — функция согласования ключей (современная замена ECDH на кривой Curve25519).
- **Постквантовые** — устойчивы к атакам квантового компьютера (на основе решёток и т.п.).
  - **ML-KEM** — механизм инкапсуляции ключа (для обмена ключами).
  - **ML-DSA** — постквантовая подпись (основной стандарт).
  - **FN-DSA** — подпись на решётках, компактные подписи/ключи.
  - **SLH-DSA** — подпись на хэш-функциях (консервативный, «страховочный» вариант).

### 3. Электронная подпись
**Что это:** подтверждение авторства и целостности сообщения. Подписывает **закрытый** ключ, проверяет **открытый**.

- **На основе эллиптических кривых** — компактные и быстрые подписи.
  - **ECDSA** — стандартная подпись на кривых.
  - **EdDSA** — детерминированная, устойчивее к утечкам/ошибкам.
    - **Ed25519** — основной практический выбор.
    - **Ed448** — повышенная стойкость.
  - **ДСТУ 4145-2002** — украинский национальный стандарт подписи.
  - **ГОСТ Р 34.10-2012** — российский национальный стандарт.
- **На основе факторизации чисел**
  - **RSA** — классическая подпись (PKCS#1 v1.5).
  - **RSA-PSS** — улучшенная вероятностная схема, рекомендуется вместо «голого» RSA.
- **На основе дискретного логарифмирования**
  - **DSA** — старый стандарт подписи.
  - **ГОСТ Р 34.10-94** — ранний российский стандарт (устарел).
  - **Схема Шнорра** — лежит в основе многих современных протоколов (в т.ч. EdDSA).
- **Постквантовые**
  - **ML-DSA** — основной постквантовый стандарт подписи.
  - **FN-DSA** — компактные подписи на решётках.
  - **SLH-DSA** — подпись на хэшах, консервативный запасной вариант.

### 4. Асимметричное шифрование
**Что это:** шифрование **открытым** ключом, расшифровка — **закрытым**. Обычно применяется к ключам/небольшим данным, а не к большим файлам.

- **На основе факторизации чисел**
  - **RSA** — шифрование открытым ключом (медленнее симметрики).
- **На основе дискретного логарифмирования**
  - **ElGamal** — вероятностное шифрование; даёт разные шифртексты для одного и того же текста.
- **На основе эллиптических кривых**
  - **ECIES** — гибридная схема: ECC-согласование ключа + симметричное шифрование данных.

### 5. Симметричное шифрование
**Что это:** один и тот же ключ и для шифрования, и для расшифровки. Быстро, используется для основных объёмов данных.

- **Блочные** — шифруют данные блоками фиксированного размера (обычно 128 бит).
  - **AES** — мировой стандарт.
  - **ГОСТ Р 34.12-2015** — российский стандарт («Кузнечик»/«Магма»).
  - **Camellia** — японский стандарт, эффективен аппаратно.
  - **Twofish** — финалист конкурса AES, гибкий и быстрый.
  - **Serpent** — финалист AES, консервативно стойкий.
- **Поточные** — шифруют побитно/побайтно, генерируя поток ключа; удобны для потоковых данных.
  - **ChaCha20** — современный быстрый потоковый шифр.
  - **Salsa20** — предшественник ChaCha20.
  - **eSTREAM** — конкурс потоковых шифров; ниже — его финалисты/победители.
    - **HC-128 / HC-256** — быстрые программные потоковые шифры.
    - **Rabbit** — высокоскоростной потоковый шифр.
    - **Trivium** — очень лёгкий, хорош для аппаратуры.
    - **Grain** — лёгкий, ориентирован на ограниченные устройства.
- **AEAD** — «шифрование с аутентификацией»: одновременно шифрует и проверяет целостность (защита от подмены).
  - **AES-GCM** — самый распространённый AEAD-режим (TLS и др.).
  - **ChaCha20-Poly1305** — быстрый AEAD, хорош там, где нет аппаратного AES (мобильные, встраиваемые).

### 6. KDF (функции формирования ключа)
**Что это:** преобразование исходного секрета (пароля, общего секрета, мастер-ключа) в один или несколько криптографических ключей нужной длины.

- **Деривация ключей** — из «хорошего» секрета делают ключи для конкретных целей.
  - **HKDF** — стандартная деривация на основе HMAC (из общего секрета → ключи).
  - **KBKDF** — деривация ключей по стандарту (NIST SP 800-108), для протоколов/систем.
- **Хэширование паролей** — специально **медленные и затратные по памяти** функции, чтобы затруднить перебор паролей.
  - **Argon2** — победитель конкурса Password Hashing; лучший современный выбор.
    - **Argon2i** — устойчив к атакам по сторонним каналам (таймингам).
    - **Argon2d** — максимально стоек к перебору на GPU/ASIC, но чувствителен к тайминг-атакам.
    - **Argon2id** — гибрид (рекомендуемый по умолчанию).
  - **scrypt** — затратен по памяти, хорош против GPU/ASIC.
  - **bcrypt** — старый, но всё ещё пригодный; ограничен длиной пароля.
  - **PBKDF2** — простой и повсеместно поддерживаемый, но слабее против современных атак (нет memory-hardness).

## Библиотеки

1. **System.Security.Cryptography** — встроенная стандартная библиотека .NET; по возможности задействует аппаратное ускорение процессора или функции ОС (CNG на Windows, OpenSSL на Linux).
2. **BouncyCastle.Cryptography (NuGet)** — самая мощная и всеобъемлющая сторонняя библиотека; незаменима для редких, архивных, национальных (ГОСТ) и самых свежих постквантовых алгоритмов, ещё не добавленных в стандартный .NET.
3. **NSec.Cryptography (NuGet)** — современная библиотека, ориентированная на алгоритмы Дэниела Бернштейна (семейство NaCl/libsodium: Ed25519, X25519, ChaCha20).

### Краткие пояснения

- **`IBlockCipher` + режим:** в BouncyCastle «движок» (`AesEngine`) реализует `IBlockCipher`, а режим (CBC, CTR) навешивается обёрткой `BufferedBlockCipher` / `PaddedBufferedBlockCipher`. Поэтому в таблице интерфейс один, но для полноценного шифрования нужна пара «engine + mode».
- **`IAeadCipher` vs `IAeadBlockCipher`:** для блочных AEAD (AES-GCM) используется `IAeadBlockCipher`, для поточных (ChaCha20-Poly1305) — `IAeadCipher`. На практике оба дают одинаковый паттерн вызова.
- **`ISigner`:** покрывает и «классические», и «специфические» (ДСТУ, ГОСТ, Шнорр), и постквантовые подписи (ML-DSA, FN-DSA, SLH-DSA) — это самый унифицированный интерфейс во всей таблице.
- **KDF vs хэши паролей:** HKDF/KBKDF унифицированы через `IDerivationFunction`, а Argon2/scrypt/bcrypt/PBKDF2 — нет, у каждого свой класс-генератор с методом `GenerateBytes`. Это осознанное разделение: у парольных KDF разные параметры (memory-hardness, соль, стоимость), которые плохо ложатся в один интерфейс.
